# Evaluation Criteria

This document outlines the criteria for evaluating task performance with both Edge Copilot and GitHub Copilot. Use these guidelines when self-assessing your work and providing feedback.

## General Evaluation Criteria

For all tasks, consider the following general criteria:

### Time Efficiency
- **5**: Completed significantly faster than expected
- **4**: Completed somewhat faster than expected
- **3**: Completed in expected time
- **2**: Completed somewhat slower than expected
- **1**: Completed significantly slower than expected

### Tool Satisfaction
- **5**: Extremely satisfied with the tool's performance
- **4**: Very satisfied with the tool's performance
- **3**: Moderately satisfied with the tool's performance
- **2**: Somewhat dissatisfied with the tool's performance
- **1**: Extremely dissatisfied with the tool's performance

### Quality Score
- **5**: Exceptional quality, exceeds requirements
- **4**: High quality, fully meets requirements
- **3**: Acceptable quality, meets basic requirements
- **2**: Below average quality, partially meets requirements
- **1**: Poor quality, fails to meet requirements

## Task-Specific Evaluation Criteria

### Unit Testing Tasks

#### Test Coverage
- **5**: Tests cover all functionality including edge cases and error conditions
- **4**: Tests cover main functionality and some edge cases
- **3**: Tests cover basic functionality
- **2**: Tests cover only partial functionality
- **1**: Tests are minimal or ineffective

#### Edge Cases Handled
- **5**: All possible edge cases identified and handled
- **4**: Most important edge cases identified and handled
- **3**: Some edge cases identified and handled
- **2**: Few edge cases identified and handled
- **1**: No edge cases identified or handled

#### Test Quality
- **5**: Tests are robust, maintainable, and follow best practices
- **4**: Tests are well-structured and mostly follow best practices
- **3**: Tests are functional but could be improved
- **2**: Tests have structural issues or don't follow best practices
- **1**: Tests are poorly structured and difficult to maintain

### Function Creation Tasks

#### Functionality Completeness
- **5**: Function fully implements all requirements with additional improvements
- **4**: Function fully implements all requirements
- **3**: Function implements core requirements
- **2**: Function partially implements requirements
- **1**: Function fails to implement key requirements

#### Code Efficiency
- **5**: Code is highly optimized and efficient
- **4**: Code is well-optimized
- **3**: Code has acceptable efficiency
- **2**: Code has some inefficiencies
- **1**: Code has significant inefficiencies

#### Code Quality
- **5**: Code is exceptionally clean, readable, and follows best practices
- **4**: Code is clean, readable, and mostly follows best practices
- **3**: Code is functional with acceptable readability
- **2**: Code has readability or structure issues
- **1**: Code is difficult to read or understand

### Code Review Tasks

#### Issue Identification
- **5**: Identifies all issues including subtle bugs and optimization opportunities
- **4**: Identifies most issues including some subtle ones
- **3**: Identifies obvious issues
- **2**: Identifies only some obvious issues
- **1**: Fails to identify most issues

#### Suggestion Quality
- **5**: Provides excellent, detailed suggestions for improvement
- **4**: Provides good, actionable suggestions
- **3**: Provides basic suggestions
- **2**: Provides limited or vague suggestions
- **1**: Provides unhelpful or incorrect suggestions

#### Review Comprehensiveness
- **5**: Review is thorough and covers all aspects of the code
- **4**: Review covers most important aspects of the code
- **3**: Review covers basic aspects of the code
- **2**: Review is limited in scope
- **1**: Review is superficial

### Documentation Tasks

#### Clarity
- **5**: Documentation is exceptionally clear and easy to understand
- **4**: Documentation is very clear
- **3**: Documentation is adequately clear
- **2**: Documentation has some clarity issues
- **1**: Documentation is unclear or confusing

#### Completeness
- **5**: Documentation covers all aspects thoroughly
- **4**: Documentation covers most aspects well
- **3**: Documentation covers basic information
- **2**: Documentation is missing important information
- **1**: Documentation is severely lacking

#### Structure and Format
- **5**: Documentation is perfectly structured and formatted
- **4**: Documentation is well-structured and formatted
- **3**: Documentation has acceptable structure and format
- **2**: Documentation has structure or format issues
- **1**: Documentation is poorly structured or formatted

## RS Copilot Integration Evaluation

- **5**: Tool perfectly recognizes and applies RS Copilot patterns
- **4**: Tool recognizes and mostly applies RS Copilot patterns
- **3**: Tool shows some understanding of RS Copilot patterns
- **2**: Tool shows limited understanding of RS Copilot patterns
- **1**: Tool fails to recognize RS Copilot patterns

### Code Standards Adherence
- **5**: Generated code perfectly adheres to RS Copilot standards
- **4**: Generated code mostly adheres to RS Copilot standards
- **3**: Generated code partially adheres to RS Copilot standards
- **2**: Generated code rarely adheres to RS Copilot standards
- **1**: Generated code does not adhere to RS Copilot standards

## Tool-Specific Evaluation

### Edge Copilot
- **Character Limitations**: Did character limitations affect your ability to complete the task?
- **Context Switching**: How much did switching between browser and IDE impact your workflow?
- **Browser Integration**: How well did the tool integrate with your browser workflow?

### GitHub Copilot
- **IDE Integration**: How well did the tool integrate with your development environment?
- **Context Awareness**: How well did the tool understand your codebase?
- **Suggestion Relevance**: How relevant were the suggestions to your task?

## Business Value Assessment

When evaluating the business value of each tool, consider:

1. **Productivity Impact**: Estimated time savings compared to completing the task without AI assistance
2. **Quality Impact**: Effect on the quality of your work
3. **Learning Curve**: How quickly you could become proficient with the tool
4. **Integration Benefits**: Advantages of direct IDE integration vs. browser-based assistance
5. **ROI Potential**: Considering license costs vs. productivity gains

Your thorough evaluation using these criteria will help build a compelling case for the business value of GitHub Copilot for graduate data scientists.
