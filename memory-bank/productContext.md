# Product Context: GitHub Copilot Experiment

## Problem Statement

Graduate data scientists at Lloyds Banking Group currently only have access to Edge Copilot (browser-based), while employees Grade D and above have access to GitHub Copilot. This creates a potential productivity gap and learning opportunity disparity between graduates and more senior employees.

Key issues with the current situation:

1. **Context Switching**: Graduates must switch between their IDE and browser to use Edge Copilot, disrupting workflow and concentration.
2. **Limited Context Understanding**: Edge Copilot has limited ability to understand the full context of a codebase compared to GitHub Copilot's direct IDE integration.
3. **Character Limitations**: Edge Copilot has input character limitations that can restrict the amount of code context that can be provided.
4. **RS Copilot Integration**: Edge Copilot may have limited understanding of the bank's Risk Science (RS) Copilot library patterns and standards.

## Solution Approach

This experiment aims to quantify the benefits of providing GitHub Copilot to graduate data scientists by:

1. Conducting a controlled experiment with 8 graduates across 3 project teams
2. Having participants complete comparable tasks with both Edge Copilot and GitHub Copilot
3. Collecting standardized metrics on time, quality, and user experience
4. Analyzing the results to calculate ROI and business value

## User Experience Goals

For graduate data scientists, the ideal experience would:

1. **Reduce Context Switching**: Allow them to receive AI assistance without leaving their development environment
2. **Improve Code Quality**: Help them write better code that follows bank standards and best practices
3. **Increase Productivity**: Enable them to complete tasks more quickly and efficiently
4. **Enhance Learning**: Support their learning journey by providing contextually relevant suggestions
5. **Standardize Practices**: Help them adopt RS Copilot library patterns and standards consistently

## Business Value Proposition

Providing GitHub Copilot to graduates is expected to deliver value through:

1. **Time Savings**: Reduced time to complete common tasks
2. **Quality Improvements**: Higher quality code with fewer bugs and better adherence to standards
3. **Learning Acceleration**: Faster onboarding and skill development for graduates
4. **Standardization**: More consistent use of approved patterns and libraries
5. **Positive ROI**: Cost savings that exceed the license investment

## Stakeholders

- **Graduate Data Scientists**: Primary users who will benefit from the tool
- **Team Leaders**: Responsible for graduate productivity and development
- **Technology Leadership**: Decision-makers for tool investments
- **Risk Science Team**: Owners of the RS Copilot library and coding standards

## Success Metrics

The experiment will measure success through:

1. **Quantitative Metrics**:
   - Time to complete tasks
   - Number of iterations required
   - Context switching frequency
   - Self-assessed quality scores

2. **Qualitative Feedback**:
   - User satisfaction ratings
   - Specific examples of tool benefits
   - Observations about RS Copilot library integration
   - Preferences and recommendations

3. **Business Metrics**:
   - Calculated time savings
   - Estimated productivity improvements
   - ROI based on graduate hourly cost vs. license cost
   - Payback period for the investment
